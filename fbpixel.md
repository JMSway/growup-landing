## 1. Какие события мы настроили

| Событие | Тип | Когда срабатывает | Что означает |
|---|---|---|---|
| `PageView` | Стандартное | При загрузке страницы | Человек зашёл на сайт |
| `ViewContent` | Стандартное | При прокрутке на 25% | Начал читать, заинтересовался |
| `Scroll50` | Кастомное | При прокрутке на 50% | Читает активно, вовлечён |

## 2. Воронка — логика прокрутки

```
PageView (100% зашедших)
    ↓ ~60-70% обычно доскроливают до 25%
ViewContent (заинтересованные)
    ↓ ~40-50%
Scroll50 (вовлечённые читатели)
    ↓ ~25-35%
Scroll75 (горячие читатели)
    ↓ ~15-25%
Scroll90 (прочитали всё)
    ↓ ~3-10%
Lead (кликнули WhatsApp)
```

**Конверсия воронки в норме:**
- PageView → Lead: 1–5% (хороший лонгрид)
- PageView → Scroll90: 15–25%

## 3. Аудитории ретаргетинга (Custom Audiences)

Создаются в: Meta Ads Manager → Аудитории → Создать аудиторию → Пользовательская аудитория → Сайт

| Аудитория | Событие | Период | Зачем |
|---|---|---|---|
| **Все посетители** | PageView | 30 дней | Широкий ретаргетинг |
| **Заинтересованные** | ViewContent | 30 дней | Читали, но не кликнули |
| **Горячие читатели** | Scroll90 | 30 дней | Прочитали всё — дожим |
| **Нажали WhatsApp** | Lead | 60 дней | Самая тёплая, исключение или CAPI |
| **Не конвертировались** | ViewContent БЕЗ Lead | 30 дней | Ретаргетинг на тех кто читал но не написал |

### Как создать аудиторию "читал но не написал":
1. Ads Manager → Аудитории → Создать → Пользовательская аудитория → Сайт
2. Включить: `ViewContent` за 30 дней
3. Исключить: `Lead` за 30 дней
4. Назвать: `Читал лонгрид — не написал`

## 4. Похожие аудитории (Lookalike)

Создаются в: Аудитории → Создать → Похожая аудитория → выбрать источник

| Источник (seed) | Размер LAL | Когда использовать |
|---|---|---|
| `Lead` (нажали WhatsApp) | 1% | Холодный трафик — самые похожие на покупателей |
| `Scroll90` (прочитали всё) | 1–2% | Холодный трафик — похожи на тех кто читает лонгриды |
| `ViewContent` (25% скролл) | 2–3% | Более широкая аудитория, для масштабирования |

> **Важно:** для создания Lookalike нужно минимум **100 уникальных пользователей** в аудитории-источнике. Для Lead — минимум 100 кликов по WhatsApp.

## 5. Стратегия рекламных кампаний

### Фаза 1 — Сбор данных (первые 50–100 лидов)

Пока данных мало, не запускать ретаргетинг. Сначала собрать аудитории.

| Кампания | Аудитория | Цель | Бюджет |
|---|---|---|---|
| Холодный трафик | Интересы: образование, языки, бизнес / гео: Казахстан | Трафик / Просмотры страниц | Стартовый |

### Фаза 2 — Ретаргетинг (после 50+ Lead)

| Кампания | Аудитория | Посыл | Цель |
|---|---|---|---|
| Горячий ретаргетинг | Scroll90 без Lead | «Ты почти решился — вот ещё один аргумент» | Lead |
| Тёплый ретаргетинг | ViewContent без Lead | «Помнишь, читал про 5 млн в месяц?» | Lead |

### Фаза 3 — Масштабирование (после 100+ Lead)

| Кампания | Аудитория | Цель |
|---|---|---|
| LAL от Lead | Похожие 1% на тех кто нажал WhatsApp | Трафик на лонгрид |
| LAL от Scroll90 | Похожие 1–2% на горячих читателей | Трафик на лонгрид |

## 7. Оптимизация кампаний — под какое событие

| Цель кампании | Событие оптимизации | Когда |
|---|---|---|
| Охват / узнаваемость | PageView | Всегда |
| Вовлечение | ViewContent | Когда мало данных |
| Качественный трафик | Scroll90 (когда 50+ событий/нед) | После накопления |
| Лиды | Lead (когда 50+ событий/нед) | Основная цель |

> Meta нужно минимум **50 событий в неделю** по одному типу, чтобы алгоритм мог оптимизировать под него. До этого — оптимизация под PageView или ViewContent.

## 8. Диагностика — если что-то не работает

| Симптом | Причина | Решение |
|---|---|---|
| В Тестировании событий нет событий | Нет `?test_event_code=TESTxxxxx` в URL | Добавить параметр в адрес |
| В Обзоре нет данных сегодня | Задержка агрегации Meta | Ждать 30 мин — 3 часа |
| Lead приходит с `content_name: unknown` | Кнопка без нужного CSS класса | Проверить классы кнопок |
| 0 сайтов в боковой панели | Верификация домена не сделана | Не влияет на работу, игнорировать |
| Pixel не обнаружен в Event Setup Tool | X-Frame-Options блокирует iframe | Убрать из `_headers` (уже исправлено) |
| События идут только с test_event_code | Тест с параметром в URL | Открыть чистый URL без параметра |

## 11. Conversions API (CAPI) — серверное дублирование событий

Каждое событие из воронки (`ViewContent`, `Scroll50/75/90`, `Lead`) теперь отправляется **дважды**:

1. Браузерный пиксель — `fbq(method, name, params, { eventID })`
2. Cloudflare Pages Function `functions/api/capi.js` (роут `/api/capi`) — форвардит то же событие в Meta Graph API server-side, с тем же `event_id`

Meta автоматически **дедуплицирует** пару браузер+сервер по совпадению `event_name` + `event_id` — событие не задвоится в Обзоре, зато повышается match quality и переживают блокировщики рекламы/ITP на стороне браузера.

### Что уходит на сервер (`user_data`)
- `client_ip_address`, `client_user_agent` — из заголовков запроса Cloudflare
- `fbp` / `fbc` — куки пикселя, если есть (`_fbp` ставится всегда, `_fbc` только если пришёл по рекламной ссылке с `fbclid`)

### Настройка (сделать один раз, вручную — я не имею доступа к аккаунтам)

1. Meta Events Manager → источник данных (пиксель `Longrid_pixel_growUp`) → **Настройки → Conversions API → Создать токен доступа вручную** → скопировать токен
2. Cloudflare Dashboard → Workers & Pages → проект сайта → **Settings → Environment variables** → добавить `META_CAPI_TOKEN` (тип **Secret**, окружение Production) → значение = токен из шага 1 → Save → **Redeploy**
3. Проверка: открыть `https://growup.onecontract.kz/?test_event_code=TESTxxxxx`, прокрутить страницу и кликнуть по WhatsApp-кнопке → в Events Manager → «Тестирование событий» события должны приходить с пометками **Browser** и **Server** одновременно, с одинаковым Event ID

Если `META_CAPI_TOKEN` не задан, функция отвечает `501` и молча не мешает браузерному пикселю (обёрнуто в try/catch на клиенте) — сайт полностью безопасен и без токена, CAPI просто не активен.

### Событие Lead — добавлены value/currency

`Lead` теперь шлёт `value: 4990, currency: 'KZT'` — это стандартные параметры, по которым Meta может оптимизировать кампании под ценность/ROAS, а не только под количество кликов.
